# frameworks.run

TanStack Start + React + Tailwind CSS, deployed to Cloudflare Workers. Pages render per request, including benchmark tables/charts and query-string selections, then hydrate for filtering, navigation and hover details. The website reads this repository's validated benchmark captures and feature evidence; it does not maintain a second measurement dataset.

The migration began with the official getting-started CLI:

```sh
bun x @tanstack/cli@latest create frameworks-run-start \
  --framework React --build-tool vite --package-manager bun \
  --deployment cloudflare --toolchain biome --no-examples --no-git
```

All authored website code uses `.ts` or `.tsx`, including build/deployment scripts and tests. Existing benchmark adapters retain their measured source and runtimes; typed declarations describe the shared benchmark APIs consumed by the site.

## Develop

From the repository root:

```sh
bun install --frozen-lockfile
bun run --cwd site dev
```

Open `http://127.0.0.1:4317`. Vite provides React Fast Refresh and Tailwind updates. Validated capture and feature-evidence changes regenerate imported data automatically. Set `PORT` to choose another port.

Use the pinned Bun 1.4.2 runtime for package management, scripts, builds and checks. Biome 2.6.6 handles linting/formatting; TypeScript 7's native Go compiler strictly checks all website source, scripts and tests, plus the framework suite. Cloudflare's local Vite/Miniflare HTTP bridge currently hangs under Bun 1.4.2, including for static files. `dev.ts` therefore hosts only that vendor CLI in Node >=22.12 (CI pins 26.13.0). The application executes in workerd locally and in the deployed Worker.

```sh
bun run check
bun run --cwd site test:browser
bun run --cwd site build
```

Install Playwright Chromium if needed: `bun node_modules/playwright/cli.js install chromium` from the repository root. Website checks do not require Rust, Ruby, Java, Go or a benchmark rerun.

## Structure

- `src/routes/`: TanStack Start file routes, shared HTML document, and metadata. `src/router.tsx` configures the router; `routeTree.gen.ts` is generated by its Vite plugin.
- `src/pages/` and `src/components/`: typed React pages, theme toggle, logos, dialogs and feature controls. They use TanStack Router directly.
- `src/charts/dashboard-model.ts`: allowlisted URL state and data selection, shared by server rendering and browser interactions. Each request owns its state.
- `src/charts/chart-markup.ts`: shared SVG/table rendering. D3 enhances the same server-rendered marks after hydration; results are not created only in a browser effect.
- `src/app.css`: Tailwind theme and component layer, with stable selectors for D3 geometry, hover/focus states and accessible controls. React layouts use utility classes. `theme-tokens.css` and the small theme bootstrap apply saved/system appearance before first paint. The previous individual page/chart stylesheets are removed.
- `prepare-data.ts`: capture/source validation, generated data, provenance and canonical fixture previews.
- `build.ts`: validated data preparation and the standard TanStack Start/Cloudflare Vite build. `dist/client/` contains assets; `dist/server/` contains the Worker and generated Wrangler configuration.

`.generated/`, `.wrangler/` and `dist/` are disposable outputs. Fixture preview HTML remains generated from the measured workload contract, including deliberate escaping examples. It is benchmark evidence, separate from the website's React pages.

## Measurements and evidence

| Source                                         | View          |
| ---------------------------------------------- | ------------- |
| `benchmarks/rendering/results/latest.json`     | SSR Rendering |
| `benchmarks/framework-ssr/results/latest.json` | Framework SSR |
| `benchmarks/http/results/latest.json`          | HTTP          |
| `benchmarks/streaming/results/latest.json`     | Streaming     |
| `benchmarks/cold-start/results/latest.json`    | Startup       |

`data.ts` uses shared statistics and validators. Authored site inputs live under [`data/`](data/README.md), grouped into performance, features and branding. `data/performance/catalog.json` contains project metadata, never timings. Builds reject invalid captures, preserve original JSON bytes in `dist/client/data/captures/`, and emit normalized results and SHA-256 provenance under `dist/client/data/`.

New selected captures flow into the next build automatically. Dates, machines, versions and output boundaries retain their original meaning. Contributor smoke runs do not replace publication pointers. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the capture and source-retention protocol.

Feature definitions live in `data/features/definitions.json`, additional projects in `data/features/projects.json`, and final primary-source findings in one `data/features/reviews/<framework>.json` per project. `feature-schema.ts` defines their TypeScript types; `features-data.ts` discovers reviews, validates their feature IDs, statuses and evidence, and joins them to projects. Aggregate dates follow the individual reviews. One registry drives React profiles, matrix, overview and downloadable `data/features.json`. Supported totals count built-in, official-package and third-party support; qualified and not-established findings stay separate. These totals describe documentation coverage, not API quality.

## Cloudflare and PR previews

The official Cloudflare Vite adapter builds the TanStack Start server entry. Wrangler automatically reads its generated configuration from `.wrangler/deploy/config.json`; keep the source `wrangler.json` pointed at `@tanstack/react-start/server-entry`. Preview and production publication upload both the Worker and its matching client assets.

`.github/workflows/site.yml` validates every PR, including provenance, type checks, browser interactions and a contributor smoke run. Same-repository PRs then upload a Worker version with `--preview-alias pr-N`, verify its deployed SSR HTML, filtered feature view and hover interactions, and publish a stable link in a bot comment and GitHub deployment. Fork PRs run checks without deployment credentials.

Preview versions do not change production traffic. Pushes to `main` deploy the just-validated build to `frameworks.run`; an explicitly selected manual deployment on `main` is also supported. The scoped `CLOUDFLARE_API_TOKEN` Actions secret authorizes the existing `frameworks-run` Worker. Rotate it before expiration; credentials never belong in source.

```sh
bun run --cwd site deploy:check  # Build and Wrangler dry-run
bun run --cwd site deploy        # Publish production when authorized
```

The browser suite checks the built app through Cloudflare's local runtime. It includes JavaScript-disabled requests for comparison tables, selected workload bars, Framework SSR, streaming panels and filtered feature matrices, plus hydration and interaction checks.

Old `.html` document URLs redirect through `public/_redirects`; they do not need application routes.
